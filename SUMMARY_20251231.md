## Critical Bug Discovered: PowerShell 7 Empty String Argument Passing

### The Problem

**PowerShell 7.3.0+ introduced a breaking change** in how empty strings are passed to external commands:

**PowerShell 5.1 behavior:**
```powershell
$empty = ''
echoargs.exe arg1 $empty arg2
# Result: 2 arguments (empty string filtered out)
# Command line: echoargs.exe arg1 arg2
```

**PowerShell 7+ behavior:**
```powershell
$empty = ''
echoargs.exe arg1 $empty arg2
# Result: 3 arguments (empty string passed as "")
# Command line: echoargs.exe arg1 "" arg2
```

### Impact on AU Module

The AU module (archived in 2022) has this code in `Push-Package.ps1`:

```powershell
$force_push = if ($Env:au_ForcePush) { '--force' } else { '' }
$packages | ForEach-Object { choco push $_.Name --api-key $api_key --source $push_url $force_push }
```

When `au_ForcePush` is unset:
- **PowerShell 5.1**: Empty string filtered out, command works fine
- **PowerShell 7**: Empty string passed as `""`, choco interprets it as a filename, causes "file not found" error

### Why chocolatey-community Doesn't Hit This Bug

The chocolatey-community/chocolatey-packages repository uses:
- **AppVeyor CI** with **PowerShell 5.1** (Windows PowerShell)
- PowerShell 5.1 has the legacy behavior where empty strings are filtered
- They never encounter the bug

### Our Environment

- **GitHub Actions** with **PowerShell 7** (default on windows-latest)
- PowerShell 7 has the new behavior where empty strings become `""`
- We hit the bug immediately

### Solutions Attempted

#### Solution 1: `$PSNativeCommandArgumentPassing = 'Legacy'` (FAILED locally)
```powershell
$PSNativeCommandArgumentPassing = 'Legacy'
.\update_all.ps1
```

**Status**: 
- ✅ Works in GitHub Actions workflow
- ❌ Fails when run locally from interactive shell
- **Root cause**: AU runs update scripts in background jobs (separate processes) that don't inherit the preference variable from interactive shells

#### Solution 2: `$env:au_ForcePush = 'false'` (WORKS everywhere)
```powershell
$env:au_ForcePush = 'false'  # String 'false' is truthy, sets $force_push = '--force'
.\update_all.ps1
```

**Status**: ✅ Works in both GitHub Actions and local execution

**How it works**:
- The string `'false'` is truthy (non-empty), so AU sets `$force_push = '--force'`
- `--force` is a valid choco push flag that allows re-pushing existing versions
- No empty string, no trailing space, no bug

**Trade-off**: Enables force-push mode, which may not be desired in all scenarios

### Current Implementation

**GitHub Actions workflow** (`update.yml`):
```yaml
- shell: pwsh
  run: |
    $PSNativeCommandArgumentPassing = 'Legacy'
    & ${{ github.workspace }}\update_all.ps1
```
Uses `$PSNativeCommandArgumentPassing = 'Legacy'` (works in workflow context)

**Local force-push script** (`force-push-elixir.ps1`):
```powershell
$env:au_ForcePush = 'false'
$env:au_Push = 'true'

```
Uses `au_ForcePush='false'` workaround (works everywhere)

## Key Learnings

### 1. PowerShell Version Matters
- PowerShell 5.1 and 7 have different behaviors for external command arguments
- Always test automation scripts on the target PowerShell version
- Background jobs may not inherit preference variables from interactive shells

### 2. AU Module Limitations
- Archived in 2022, no longer maintained
- Contains bugs that manifest in PowerShell 7
- Community still uses it extensively (on PowerShell 5.1)
- Workarounds needed for PowerShell 7 compatibility

### 3. Chocolatey Moderation Requirements
- Embedded binaries require LICENSE.txt
- Downloaded files require checksum validation
- VERIFICATION.txt must document file sources and checksums
- 10-version moderation limit requires careful batch processing

### 4. Environment Variables in PowerShell
- Cannot be `$null` - must use falsy values like `$false`
- Boolean `$false` converts to string `"False"` when assigned to environment variable
- String `"False"` is truthy in PowerShell conditionals
- Must use string comparison (`-eq 'true'`) to get boolean behavior

### 5. GitHub Actions vs Local Execution
- Workflows run in clean, isolated environments
- Preference variables may behave differently in workflow context vs interactive shells
- Background jobs inherit environment differently in each context
- Always test locally before relying on workflow-only testing

## Technical Details

### Package Fix Versions

When forcing updates, AU adds a package fix version suffix:
- Original: `1.19.4`
- With fix: `1.19.4.20251231` (YYYYMMDD format)

This allows re-pushing the same upstream version with package fixes.

### AU Background Jobs

AU runs package updates in PowerShell background jobs (`Start-Job`) for parallel processing:
- Each package update runs in isolated process
- Environment variables are inherited
- Preference variables may not be inherited from interactive shells
- This is why `$PSNativeCommandArgumentPassing` works in workflows but not locally

### Checksum Calculation

AU's `Get-RemoteFiles` function:
- Downloads files from URLs specified in `au_GetLatest`
- Calculates checksums based on `-ChecksumFor` parameter
- Updates VERIFICATION.txt with checksums
- Options: `none`, `32`, `64`, `all`
- Use `64` for 64-bit only packages, `all` for both 32/64-bit

### File Embedding

For embedded binaries:
1. `Get-RemoteFiles` downloads to `tools/` directory
2. Files are included in nupkg via nuspec `<files>` section
3. `chocolateyInstall.ps1` uses `Install-ChocolateyZipPackage` with local file
4. Must include LICENSE.txt and VERIFICATION.txt in tools/

## Lessons Learned

### 1. Test on Target Platform
Always test automation scripts on the actual platform they'll run on. PowerShell version differences can cause subtle bugs.

### 2. Archived Modules Can Have Hidden Issues
The AU module works fine on PowerShell 5.1 (where it was developed) but has bugs in PowerShell 7. Always check if dependencies are actively maintained.

### 3. Background Jobs Complicate Preference Variables
Preference variables like `$PSNativeCommandArgumentPassing` don't reliably propagate to background jobs in interactive shells, but work in script contexts.

### 4. Environment Variables Are Strings
PowerShell converts all environment variable values to strings. Boolean `$false` becomes string `"False"`, which is truthy in conditionals.

### 5. Empty String vs Null
In PowerShell 7, there's a critical difference:
- Empty string `''` is passed as `""` to external commands
- `$null` is filtered out and not passed at all
- Use `$null` for optional arguments to external commands

### 6. Force-Push Has Valid Use Cases
While generally avoided, `--force` flag is legitimate for:
- Re-pushing packages with fixes (same version, updated content)
- Recovering from failed pushes
- Testing in development

### 7. Generator Pattern for Multi-Version Packages
When software supports multiple versions of a dependency:
- Use generator scripts to create packages from templates
- Keep templates in source control, not generated packages
- Automate version detection from upstream sources
- Reduces maintenance burden significantly
